# Аудит кабінету Meta Ads (audit-kit)

Ти ведеш користувача через готові скрипти пакета (`KIT` = папка audit-kit). Скрипти детерміновані:
твоя робота це підготувати дані, налаштування й перевірити результат. Нічого не вигадуй: усі цифри
в документі беруться з файлів. Якщо даних немає, скажи про це.

## Крок 0. Підготовка

1. Запитай папку `KIT` і робочу папку клієнта (де буде `config.json` і `data/`).
2. Перевір, що є Python 3.10+ і `pip install -r KIT/requirements.txt` виконано. Нічого не став без згоди.
3. Створи `config.json` з `KIT/config.example.json`. Запитай: назву клієнта, період, адресу сайту, маржу клієнта до реклами (якщо знає),
   чи потрібне знеособлення (`anonymize`) для публічного прикладу.
4. **Токен ніколи не проси в чаті й не читай із файлів.** Користувач сам задає `META_TOKEN` у середовищі.

## Крок 1. Дані (обери режим)

**Режим А: токен є.** `python KIT/fetch_meta.py --config config.json`. Якщо помилка прав або ліміту, поясни, що це.

**Режим Б: токена немає, дані знімаєш через браузер.** Потрібен дозвіл користувача на кожне завантаження файлу.
1. Відкрий Ads Manager потрібного кабінету в браузері користувача, мова інтерфейсу English.
2. Постав період (кнопка дат, Custom, формат MM/DD/YYYY, Update). URL-параметр періоду Meta ігнорує.
3. Для кожного файлу з таблиці в `README.md` зроби експорт: Export (стрілка) → Export as .csv. Експорт триває до хвилини.
4. Файли лягають у Завантаження: перейменуй і перенеси в `data/` під потрібними іменами.
5. Не читай таблицю зі сторінки: вона віртуалізована, у вікні видно кілька рядків. Працюй лише з експортами.
6. Якщо в браузері відкрито зведений звіт з кількома кабінетами, не експортуй його: у файл потраплять дані інших клієнтів.

## Крок 2. Сайт

1. Адреса посадкової береться з `site_url`. Якщо відомі URL, куди ведуть оголошення, краще перевіряти їх.
2. `python KIT/site_check.py --config config.json` (потрібен ключ `PSI_API_KEY`; без нього часто помилка 429).
3. Якщо PageSpeed недоступний: відкрий сторінку в браузері, зніми швидкість і вагу (Performance API) та
   запиши у `data/site.json` поле `psi` із `"source": "browser"` та числами `fcp_s`, `load_s`, `total_kb`, `requests`.
4. Перший екран і оффер оціни очима й додай у `data/site.json` у масив `notes`
   (`tag`, `title`, `text`, за потреби `action`, `effect`, `urgency`). Пиши лише побачене.

Приклад `site.json` (ручні заміри):
```json
{"url": "https://example.com/",
 "psi": {"source": "browser", "fcp_s": 2.5, "load_s": 5.1, "total_kb": 9640, "requests": 72},
 "html": {"h1_count": 0, "images_total": 89, "images_no_alt": 72, "viewport": true, "meta_description": "є"},
 "notes": [{"tag": "УВАГА", "title": "Перший екран не продає товар", "text": "Перший екран це банер, а не пропозиція.",
            "action": "Вести рекламу на картку товару", "effect": "вища конверсія", "urgency": "цього тижня"}]}
```

## Крок 3. Аналіз і документ

`python KIT/run_audit.py --config config.json --skip-fetch --skip-site` (дані вже в `data/`, сайт перевірений).

## Крок 4. Перевірка перед віддачею (обов'язково)

1. Відкрий `work/report.json`, переглянь знахідки. Кожна має спиратися на цифру. Висновки, які виглядають сумнівно, поясни користувачу.
2. Переконайся, що суми збігаються між файлами (витрати в кампаніях, оголошеннях, плейсментах мають бути однакові).
3. Нагадай: тип аудиторії й формат визначаються за назвами; перевір шаблони в `config.json`.
4. Для знеособленого документа перечитай текст і переконайся, що немає назв клієнта, домену, імен людей.
5. Покажи користувачу 3 головні знахідки й що не перевірено. Не стверджуй прибутковість без маржі.

## Чого не робити

- Не проси й не читай токени, паролі, `.env`.
- Не завантажуй файли без згоди користувача.
- Не змінюй кабінет клієнта (аудит лише читає).
- Не вигадуй цифр, бенчмарків і причин: усе, що не підтверджено даними, позначай гіпотезою.
- Не публікуй документ із реальними назвами клієнта.
