# Модуль 1: Дашборд для всіх клієнтів

> Для ШІ-агента. Спершу прочитай `SECURITY.md` і `agent/RULES.md`.

**Результат:** Дашборд по всіх кабінетах Meta, лише читання  
**Потрібно:** Business Manager, доступ до кабінетів, токен ads_read  
**Статус:** Описано підключення й логіку, скриншоти з демо-даних. Зв'язку «Meta API → дашборд» на реальних даних я не збирав: перевірте її на одному кабінеті.

## GOAL
- Зібрати для користувача дашборд по клієнтських кабінетах Meta Ads (тільки читання).

## STATUS
- Готового коду немає. Ти пишеш збирач і сторінку за цією специфікацією. Перевір на ОДНОМУ кабінеті, потім підключай решту.

## ASK_USER (по одному)
- Скільки кабінетів; ID кожного (act_...); тип результату в кожному (ліди, покупки, реєстрації); валюта; часовий пояс.
- Де житиме дашборд: Google Таблиця + Apps Script (рекомендовано) чи локальний Python + HTML.

## USER_DOES_THEMSELVES (ти токена не бачиш)
- 1) developers.facebook.com: Create App, use case Marketing API, тип Business, прив'язати до свого Business Manager.
- 2) Business Settings, Users, System users: створити reporting-bot (роль Employee). Додати йому додаток (Add people).
- 3) System user, Add assets, Ad accounts: кожен кабінет з правом лише View performance.
- 4) Generate new token: свій додаток, право лише ads_read, Never expires (або нагадування про 60 днів). Токен показується один раз.
- 5) Токен покласти в Script Properties (META_TOKEN) чи змінну середовища. Ти підказуєш текстом і не просиш значення.

## BUILD collector
- GET https://graph.facebook.com/{VERSION}/act_{ID}/insights?level=ad&time_increment=1&date_preset=yesterday
- fields=campaign_id,campaign_name,adset_id,adset_name,ad_id,ad_name,spend,impressions,clicks,reach,frequency,cpm,ctr,actions,action_values
- Пагінація за paging.next; при rate limit (коди 17, 613) пауза і повтор. Версію API звір з документацією Meta.
- Запис ідемпотентний: ключ date+ad_id, наявні рядки не перезаписувати, порожні заповнювати, нові дописувати. Ведіть журнал запусків.
- Розклад: щодня зранку. Пропущений день сам не надолужується: нагадай користувачу дивитись журнал раз на тиждень.
- Результат береться з actions за типом, що відповідає цілі кабінету (lead, purchase, ...). Охоплення й частоту між рівнями не сумуй.

## BUILD dashboard
- Огляд: витрати, результати, ціна результату, ROAS, число креативів, що вигорають, «критичні моменти», графік по днях, таблиця проєктів.
- Заглиблення: проєкт, кампанія, група, оголошення. Креативи за проєктами з фільтром статусу й пошуком.
- Звіт за день і тиждень по кожному проєкту: вердикт і три списки: Масштабувати / Звернути увагу / Вимкнути.
- Період: сьогодні, 7 днів, 14 днів, свій діапазон.

## STATUS_RULES (пороги винеси в конфіг)
- Працюють за період від 7 днів і ціною результату (CPR).
- Вигорає: CPR за останні 3 дні гірша за CPR періоду більш ніж на 1/3, або є витрати без результатів.
- Росте / Погіршується: CPR змінилась на 15% і більше проти такого ж попереднього періоду.
- Без результату: від $30 витрат і 0 результатів. Мало даних: менше $20 витрат. Новий: у попередньому періоді майже без витрат.

## VERIFY
- spend за вчора в збирачі збігається з Ads Manager для одного кабінету.
- Суми по рівнях (кампанії, групи, оголошення) збігаються. Повторний запуск не дублює рядків.

- Не перевірено на реальних даних автора. Скриншоти в PDF з вигаданих проєктів.
